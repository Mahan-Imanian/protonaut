Test your Windows game build on Proton.

Protonaut is a GitHub Action and CLI that runs your game under pinned GE-Proton on every pull request. When a change makes it crash or render black, the PR goes red, with screenshots and logs. You don't need a Steam Deck.

One step in your workflow

- uses: Mahan-Imanian/protonaut@v0
  with:
    build: dist/Windows
    exe: MyGame.exe

Runs on ubuntu-24.04. The step fails on any FAIL, writes the report to the job summary and uploads screenshots and logs. Workflows for Godot, Unity and Unreal are in the recipes.

curl -fsSL https://raw.githubusercontent.com/Mahan-Imanian/protonaut/main/install.sh | sh -s -- --with-deps
sudo protonaut setup
protonaut test dist/Windows --exe MyGame.exe --install

Or run the CLI on your own Ubuntu 24.04 machine. On your machine the game runs as your user, so only run builds you trust.

What it catches

Launch and stability

Crashes, exits with an error, missing DLLs, a game that never opens a window.

Rendering

Black or empty frames, letterboxing at 1280x800, extra "unsupported hardware" windows, error text inside the game window.

The build itself

32/64-bit and ARM64 executables, DLL imports nothing provides, files that differ only by case, anti-cheat files, launchers, Media Foundation video.

Steamworks hints

Whether the Steam Input and on-screen keyboard APIs are imported.

Missing evidence is never reported as a pass. If a screenshot can't be captured, the check says NOT_TESTED. CI also runs OpenTTD 15.3, a Godot 4.7.2 3D game and Chocolate Doom 3.0.1 through the action. See the results.

How it works

  1. Your build runs under a pinned, checksum-verified GE-Proton release with Mesa's software Vulkan driver on a headless display at 1280x800.
  2. A control program that draws a known colour runs first. If its frame can't be captured, screenshot checks report NOT_TESTED, not a false black screen.
  3. Your game runs as an unprivileged user with no network and no CI token. Protonaut records windows, screenshots and the Wine log, then stops every process.
  4. Rules turn the evidence into report.json, an HTML report, JUnit XML and a PR comment.

What it can't do

  • GE-Proton is not Valve's Proton, so a game can behave differently on a real Deck.
  • No real game proven to render through DXVK (Direct3D 9-11) is in the suite yet.
  • Rendering uses Mesa lavapipe on the CPU, so there are no performance numbers.
  • There is no Steam client, so games that require the Steam API to initialise can't be tested.
  • No controller, touch, suspend or battery testing.

FAQ

Can I test Steam Deck compatibility in CI without a Steam Deck?

Partly. Protonaut runs your Windows build under GE-Proton on a GitHub runner and catches crashes, black screens, letterboxing and error dialogs. Frame rate, controller feel and suspend still need a device.

Will a pass get my game Steam Deck Verified?

No. Valve decides that rating. A Protonaut pass cannot predict it, and Protonaut reports hardware criteria as NOT_TESTED.

Is this Valve's Proton?

No. Protonaut uses GE-Proton, a community build, because Valve's builds need a Steam login. A game can behave differently under Valve's Proton.
